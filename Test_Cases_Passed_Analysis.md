## Black Box Testing - Passed Cases

### 1. Registration Page Client-Side Validation Testing

The registration form validation has been successfully implemented and deployed across the application. Testing revealed that all input fields including name, email, contact number, address, username, and password undergo comprehensive client-side validation through JavaScript regex patterns before submission is permitted. The email validation utilizes a sophisticated regex pattern to ensure proper email format with support for common email variations. Contact number validation enforces the Indian phone number format requirement by verifying the first digit falls between 6-9 followed by exactly nine additional digits. Password validation requirements are rigorously enforced, requiring a minimum of eight characters with mandatory inclusion of uppercase letters, lowercase letters, numeric digits, and special characters from the specified character set. The validation system displays real-time error feedback to users with clear, descriptive messages indicating what corrections are needed. Invalid form submissions are prevented through JavaScript event handling, ensuring users cannot bypass validation checks on the client side.

### 2. Job Application Submission Testing

The job application submission functionality has been fully implemented and is operational in the production environment. When applicants submit applications for job vacancies, the system creates Application records in the database using Django's `get_or_create` methodology, which prevents duplicate applications for the same position while maintaining accurate application counts. The application submission process supports applicants applying to multiple positions simultaneously without data loss or corruption. The system automatically assigns the 'APPLIED' status to newly created applications and persists this information in the database with automatic timestamp recording. User feedback is provided through Django's messaging framework, displaying success messages when applications are created and warning messages if an applicant attempts to reapply for the same position. The workflow automatically redirects users back to the job category page after submission, maintaining a smooth user experience throughout the application process.

### 3. Vacancy Creation and Management Testing

Staff members have the ability to create and manage job vacancies through dedicated administrative forms. New vacancies are created by specifying essential parameters including vacancy name, number of available seats, company information, salary range, and detailed job content descriptions. All vacancy information is successfully persisted in the database with complete field preservation. Updates to vacancy details are processed correctly, modifying all specified fields while maintaining referential integrity with associated application records. The system provides confirmation messages upon successful vacancy creation and modification, assuring staff that operations have completed successfully. The vacancy management interface allows staff to view all existing vacancies, edit details through modal forms, and remove vacancies when positions are closed or filled. Updated vacancy information is immediately reflected across the platform, ensuring applicants always view current and accurate job listings.

### 4. CV Upload and File Handling Testing

The CV upload functionality has been implemented with intelligent file management capabilities. Applicants can upload their resumes through the upload interface, and the system accepts PDF file formats for processing. Upon file upload, the system implements a strategic file renaming approach that concatenates the original filename with the applicant's unique identifier, preventing filename collisions and enabling easy traceability of CV files to specific applicants. Files are stored in the designated cv_base directory within the media folder structure, ensuring organized file storage. The system creates and maintains file path references in the Applicant model's cvpath field, establishing the necessary link between applicant profiles and their uploaded documents. After successful upload, applicants are redirected to their account view page where they can verify the upload completion. The file storage system utilizes Django's FileSystemStorage to handle file operations reliably, creating appropriate directories and managing file permissions.

### 5. Applicant Search and Filter Testing

The applicant search and filtering system provides staff members with powerful capabilities to identify candidates matching specific job requirements. Staff can enter multiple keywords in comma-separated format, and the system intelligently parses these inputs, trimming whitespace and handling empty entries appropriately. The keyword-based CV analysis leverages the machine learning keyword mining algorithm to search through uploaded CV files and identify matches with specified skills and qualifications. Search results are automatically ranked by relevance score, with applicants matching more keywords appearing higher in the result list. Matching applicants are visually distinguished in the results table using color coding (table-success class for matches), making it immediately apparent which candidates meet the specified criteria. The system displays the total count of matching applicants, providing quick insights into candidate pool size. Staff can further refine results using the vacancy filter dropdown, limiting results to applications for specific positions. The system gracefully handles scenarios with no matches, displaying appropriate messaging rather than errors.

### 6. Application Status Update Testing

Staff members can update application statuses through a dropdown selection interface, allowing real-time status progression through multiple stages of the recruitment process. The application status update mechanism supports a comprehensive range of status values including APPLIED, UNDER_REVIEW, SHORTLISTED, and multiple interview round statuses. When status changes are submitted, the system persists the new status value in the Application model and automatically updates the status_updated_date timestamp field through Django's auto_now functionality. Optional notes can be attached to status updates, providing context for staff observations during the screening process. Status changes are confirmed through success messages, providing clear feedback that updates have been processed. The system intelligently determines the appropriate redirect destination based on the referring page, returning staff to either the general applicant view or the filtered results view depending on context. This functionality enables effective tracking of each applicant's progress through the recruitment pipeline.

### 7. Profile Update and Password Change Testing

All user roles—applicants, staff members, and administrators—can update their profile information through dedicated update interfaces. Profile modifications including names, email addresses, contact numbers, and professional experience are successfully saved and persisted across both the Login model and the respective user type model (Applicant or Staff). When applicants update their information, changes are simultaneously reflected in both the Login table and the Applicant table, maintaining data consistency across related models. Password updates are processed and stored in the database, enabling users to change their login credentials. The system propagates username changes across both tables, ensuring consistency between authentication records and user profile information. Experience level and educational degree information can be updated by applicants, enriching their profile data for recruitment staff review. All three user types can access their respective profile update forms, with appropriate template rendering for each role ensuring role-specific fields are displayed and editable.

## White Box Testing - Passed Cases

### 1. CV Parsing and Text Extraction Logic

The CV parsing module implements functional text extraction capabilities for PDF documents. The system iterates through all uploaded PDF files in the designated cv_base directory, using the PyPDF2 library's PdfReader to open and process each document. For multi-page documents, the parser extracts text from every page by iterating through the pages collection, concatenating all page text into a complete document representation. Text extraction is performed with case normalization, converting all extracted text to lowercase to enable case-insensitive keyword matching. The system implements error handling for file access issues, gracefully managing scenarios where files cannot be read without terminating the parsing process. CV files are associated with applicants through database queries, linking filename references to the corresponding Applicant model records. The parsing functionality successfully handles diverse PDF structures and layouts, extracting readable text content from various document formats.

### 2. Keyword Matching and Qualification Analysis

The keyword matching algorithm performs systematic analysis of CV content to identify relevant skills and qualifications. The system accepts multiple keywords as input and implements case-insensitive matching, converting both keywords and CV text to lowercase before comparison. For each keyword, the algorithm performs substring matching against the full CV text, counting matches that occur anywhere within the document. Exact phrase matching is supported, enabling searches for multi-word qualifications like "Machine Learning" or "Cloud Architecture". Multiple keyword support allows applicants to be scored based on how many required skills they possess, with applicants matching all specified keywords receiving higher scores than those with partial matches. The scoring mechanism simply counts total matches, providing a numerical value that directly reflects the quantity of matching qualifications. Results are ranked by score in descending order, automatically prioritizing candidates with the strongest skill alignment with the vacancy requirements. Staff members can easily identify qualified applicants and shortlist strong candidates based on skill match scores.

### 3. ML-Based Applicant Ranking Integration

The machine learning integration provides end-to-end ranking of applicants based on CV content analysis. When staff members submit keyword search requests, the system invokes the keyword_miner function from the ATS module, which returns a dictionary mapping applicant IDs to their calculated match scores. For each applicant in the system, the staff view retrieves the corresponding ML score from the results dictionary, defaulting to zero for applicants with no keyword matches. Applicant data is enriched with the calculated scores and passed to the template rendering engine. The template displays matching applicants with visual highlighting through Bootstrap's table-success styling, making matched candidates immediately recognizable. Match scores are available in the template context for display or further processing. Results are sorted by match score in descending order before rendering, ensuring highest-scoring applicants appear at the top of the results list. The integration gracefully handles scenarios where applicants have no matches, displaying them with zero scores rather than omitting them entirely. The system maintains accurate total match counts, informing staff of the total number of applicants meeting the search criteria.
